🔟 MindTopo 基准揭示：VLM 能看懂拓扑，却无法在行动中保持它

  • 基准构成：微软研究院发布 MindTopo，评估多模态大模型对连续性、分离、顺序、封闭与打结五类拓扑关系的推理与规划能力，全部场景由可控模拟器生成，具备精确 ground truth。
  • 核心发现：模型在静态识别上表现尚可，但进入需要多步操作保持拓扑不变的规划任务时性能大幅下滑；失败多发生在规划阶段而非感知阶段——模型会丢失已理解的结构关系或提出违反物理约束的动作。
  • 行业意义：该差距与机器人及交互式环境高度相关，如何显式携带拓扑状态成为下一代世界模型的候选方向。

DeepSeek V4 Pro 0813

764 pts · 288 comments · openrouter.ai

📌 内容总结

  • OpenRouter 上架 DeepSeek V4 Pro 0813 API 页面；当前仅 DeepSeek 官方一个上游，OpenRouter 直接转发，无多 provider 路由。
  • 标价 $0.435/M input、$0.87/M output；页面统计实际加权均价为 $0.0386/M input、$0.8696/M output，缓存命中率 91.9%。吞吐 45 tok/s，P50 延迟 1.87s，近 30 天可用性 100%。
  • 基准：GPQA Diamond 88.8%、HLE 37.5%、Terminal-Bench Hard 46.2%、SciCode 50%、τ²-Bench Telecom 96.2%；OpenRouter 自采的 AA-Omniscience 准确率 42.9%、非幻觉率 5.9%。文本模型，无视觉能力。
  • 主要流量来自 Hermes Agent、Claude Code、pi 等 agentic coding 工具，符合官方定位：低价 coding/agent 模型。
💬 讨论总结
  • 定价是最大关注点：有评论认为能力与 Opus 4.8 同档但便宜约 20 倍；若按 agentic coding 常见 cache-read/input/output 比例折算，单请求成本比 Opus 低约 60 倍。也有提醒：per-token 便宜不等于 per-task 便宜，模型可能烧 token；回复中给出的测算是按任务计仍低 1–2 个数量级。
  • 横向基准表显示：V4 Pro 0813 接近 Fable 5，但 DeepSWE、Toolathlon 等仍有差距；评论算出的几何平均分低于 GPT-5.6 Sol、Fable 5、Opus 5，略高于 Kimi-K3。另有观点称其在近一半基准落后 Kimi-K3，但更容易部署、运行成本更低。
  • 实测体验分歧明显：一个 Codex CLI 对比中，DeepSeek 跑 12m02s/$0.12 但留 bug，Grok 4.6 跑 3m18s/$1.41 无 bug；另一用户用 docker-compose 任务得出类似结论。但也有用户在 opencode 中满意，并在分布式物理引擎任务上获得无回归优化。共识倾向：简单任务性价比极高，复杂任务稳定性不如头部模型，且严重依赖 harness。
  • 工程经验：agentic loop 中应尽量保持 system prompt/history 不变，否则会打掉 DeepSeek 的缓存命中率；DeepSeek 的缓存读价格很低，保持历史稳定比压缩 context 更划算。
  • 隐私与政策风险：当前 OpenRouter 唯一 endpoint 要求开启 “Allow paid endpoints that train on request data”；有评论认为提交给 DeepSeek 的请求都应视为公开内容。企业场景中，美国/欧盟可能限制中国模型，是部分团队主动回避的原因。
  • 商业节奏：DeepSeek 官方当天开始涨价；评论认为 Flash 0731 仍是近期性价比最突出的版本，并有人给出 2x DGX Spark 约 $8000 本地跑满血 Flash 的方案。
  • 发布形式也受到批评：DeepSeek 没有官方 blog/页面，HN 只能链到 OpenRouter；OpenRouter 本身是 proprietary 服务，不该被视为模型官网。

Qwen3.8-2.4T

506 pts · 110 comments · huggingface.co

📌 内容总结

  • Qwen 发布开源权重 Qwen3.8-2.4T-A95B：总参数 2.4T、激活 95B；MoE 为 512 experts（10 routed + 1 shared），92 层，Gated DeltaNet 与 Gated Attention 混合，带 MTP。
  • 原生上下文 262,144 tokens，可扩展到约 1M；但开源版本为纯文本、强制 thinking 模式，不支持视觉/非 thinking。具备视觉、非思考、1M 默认上下文、内置工具的 Qwen3.8-Max 仅通过 Qwen Cloud 提供。
  • 基准卡片与 Opus 4.8、GPT-5.6 Sol、Fable 5 对标：PaperBench 93.0、Terminal Bench 2.1 86.6、QwenReactBench 1724、HLE w/ tools 56.2；DeepSWE 56.6、NL2Repo 55.9。脚注显示大量项目用自家 harness 评测，且 Fable 5 可能含 fallback。
  • 权重尺寸：BF16 约 4.9TB，FP8 约 2.5TB。许可接近 Kimi K3：内部使用或年收入 <$50M 免费；超过后对 serving 或 coding/productivity agent 服务有限制。
💬 讨论总结
  • 尺寸决定部署现实：“~5TB model”是多数评论的第一反应；Unsloth 1-bit quant 约 397GB，普通高端机器尚可一试，但完整 BF16 + context/KV cache 需要 7TB 级内存，属于中型公司预算。Kimi K3 参数更大，但发布时带 QAT 4-bit（~1.5TB）；Qwen 只给 BF16/FP8、没有 QAT，初期更难 serving。
  • 开源版能力阉割被集中批评：去掉视觉、限制上下文、强制 thinking，与 Qwen3.5 的开源完整度相比是倒退；“Read the room, Qwen”是代表性评论。也有人指出 DeepSeek V4 Flash / GLM-5.2 已有后接 vision tower 的先例，预计社区会给 Qwen3.8 补上视觉。
  • 基准可信度存疑：有人称模型卡 “almost too good to be true”；评论反复提到 Qwen 的 benchmark 与实际使用相关性过去不稳。同日 DeepSeek V4-Pro-0813 发布，被认为可能是对冲 Qwen 热度；两者能力相当但 DeepSeek 价格更低。
  • 对多数 HN 用户来说，真正值得等的是 Friday 发布的 Qwen3.8-27B；RTX 5090/64GB 用户无法跑 2.4T，只能选托管 API（QwenCloud、Fireworks、DigitalOcean）或等小参数版本。
  • 评论也区分了“开源权重”与“开放”：License 限制 high-revenue 商用，开源版还砍了 Qwen-Max 的卖点功能。

  • 质疑集中在基准可信度：有人称 “on paper impressive”，也有人直接说 “benchmaxxed”；还有评论怀疑两个月内所有实验室同时达到 Fable 级别，解释包括无护城河/技术扩散/基准操纵，但没有形成共识。
  • Musk 信任问题主导了非技术讨论：大量用户明确拒绝使用 xAI 产品，理由是 Musk 不可问责、政治风险、个人数据信任；有评论甚至表示更信任中国 AI 公司。也有用户认为这是双标，且 Grok 的实际体验与口碑存在明显分化。
  • 实测体验分裂：有人称 Grok 4.5 是三年里用过最差的模型，另有人称 4.5 是最喜欢的模型之一；对 4.6 多数人选择等独立测试和尘埃落定。
  • 工程/产品细节：用户发现 xAI API 默认注入 system prompt，其中“不得提及 guidelines”会压过用户 system prompt，导致模型拒绝讨论自身约束；“只允许修 local codebase 漏洞、不得写 exploit/PoC”的边界也被认为定义不清。
  • 一位自称 xAI 员工的回复称：4.6 的视觉/交互改进来自把设计原则写成可训练文字并构造 pairwise comparison 数据，承认主观性强、还有很大空间；设计师用户对此类“AI 说自己擅长设计”的声明普遍持保留态度。
  • 另外有评论提到 Grok voice mode 最近明显变笨变短，可能和响应长度控制问题有关；xAI 的定价页一度仍显示 4.5。
