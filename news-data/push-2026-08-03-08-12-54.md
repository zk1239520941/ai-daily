### 1️⃣ 吴恩达开源 OpenWorker：本地优先的“AI 同事”一周获 1.1 万 Star

* **核心发布**：吴恩达与前 Amazon Alexa 首席科学家 Rohit Prasad 联合开源桌面 AI Agent OpenWorker，MIT 协议，定位为交付成品的本地 AI 同事，发布一周星标数达 1.1 万。
* **技术架构**：Tauri 2 + React 18 桌面壳，本地 Python（FastAPI）Agent 服务器，支持 25+ 远程集成和任意 MCP 工具；模型层预置 30 个验证过的模型，并通过 aisuite 统一路由，可用 Ollama 跑本地模型。
* **权限设计**：工具调用按 read/write_local/exec/external 分四级风险，配 discuss/plan/interactive/auto/custom 五种模式；无人值守模式只改变 Agent 联系用户的方式，不提高自主权限上限，shell 命令任何模式都需确认。
* **现状**：Open Beta，Mac 版已签名支持自动更新；Windows 版未签名；暂无 Linux 版与中文界面。

🔗 [GitHub](https://github.com/andrewyng/openworker) | [官网](https://openworker.com) | [Datawhale 解读](https://mp.weixin.qq.com/s?__biz=MzIyNjM2MzQyNg==&mid=2247724896&idx=1&sn=527227ca49bfad6c7328ae73f234600d)

### 2️⃣ Google 发布第八代 TPU：训练与推理分体，TPU 8t/8i

* **核心发布**：Google Cloud 推出第八代 TPU 系统，首次拆分为训练专用 TPU 8t 与推理专用 TPU 8i 两条产品线。
* **规格**：TPU 8t 面向万亿参数预训练，9600 芯片组提供 121 exaflops 算力与 2 PB 共享内存，峰值性能为上一代 3 倍；TPU 8i 面向后训练与实时推理，通信密集任务延迟最多降低一半。
* **官方数据**：低延迟推理场景性能/美元提升最高 80%，系统可扩展至 100 万+ 芯片。
* **行业意义**：Agent 时代多轮推理对延迟高度敏感，训练与推理硬件路线分化成为明确趋势。

🔗 [Google Cloud 推文](https://x.com/googlecloud/status/2083323071897747667) | [中文解读](https://x.com/xiaohu/status/2083829267797041580)

### 3️⃣ DeepMind 新研究 SkillSmith：让模型权重成为 LLM 可读的模态

* **核心发布**：Google DeepMind 发布 SkillSmith，将模型权重前缀作为额外模态交给 LLM 原生读取，输入描述能力关系的文本后直接输出新的权重前缀，实现“指令引导的参数合成”。
* **关键变化**：技能组合从训练时操作变为推理时操作，不再需要为每个技能单独跑训练。
* **效果**：论文称其增益超过单独使用文本适配或权重适配的结果。

🔗 [论文](https://arxiv.org/abs/2607.27497) | [介绍推文](https://x.com/omarsar0/status/2083951213171925221)

### 4️⃣ Karpathy 实测：Opus 5 用 2 小时写 5500 行代码渲染《指环王》

* **核心实验**：Karpathy 给 Opus 5 一段《指环王》开头、100 万 token 预算（约 10 美元），要求用 Three.js 程序化渲染故事，模型耗时约 2 小时写出 5500 行代码并生成可运行场景。
* **核心洞察**：LLM 的耐力让“没人会花时间写的超定制代码”变成“反正便宜，为什么不呢”，指向按需生成超定制世界/临时 GTA 的可能性。
* **暴露短板**：模型无法高效观看视频或亲自游玩生成场景，只能逐点截图检查，导致视觉与逻辑瑕疵无法被快速审计，多模态与游戏内感知仍是明显缺口。

🔗 [Karpathy 推文](https://x.com/karpathy/status/2083749667410727319)

### 5️⃣ Cloudflare 启动 Agents Week：提出“Agent Cloud”概念

* **核心发布**：Cloudflare 宣布本周为 Agents Week，并重新定义要回答的问题：不是“Agent Cloud 是什么”，而是“你的 Agent 需要什么样的云”。
* **核心判断**：现有云和 Web 是为人类观看设计的；Agent 需要的是速度、结构和访问方式完全不同的原语，同时需要一个翻译层兼容人类形态的现有 Web。
* **计划**：未来五天围绕 agent 执行层原语、agentic 软件开发生命周期、组织内安全控制、agentic web 以及现实落地展开。

🔗 [Cloudflare Blog](https://blog.cloudflare.com/agents-week-welcome/)

### 6️⃣ 美团 LongCat 开源 VitaBench 2.0：长期动态智能体评测基准

* **核心发布**：美团 LongCat 团队发布 VitaBench 2.0，首个真实生活场景下的长期动态用户建模智能体基准，并全面开源。
* **规模**：56 名拟真用户、819 个任务、超 2000 个动态偏好、66 个可执行工具；平均每位用户 2093 个交互事件，平均时间跨度 1580 天。
* **关键发现**：开卷模式下最强模型 Claude-Opus-4.6 平均分刚过 0.5；接入记忆模块后多数模型性能反降；所有模型在主动提问任务上断崖下跌（Claude 家族 46.0→27.4）；DeepSeek-V4-Pro 等强模型的主要失败点从工具使用转向偏好理解。

### 1️⃣0️⃣ MIT 与哈佛研究：LLM 离真正的科学发现还很远

* **核心事实**：MIT 和哈佛研究人员发表论文《Evaluating Large Language Models in Scientific Discovery》，提出 SDE 评估框架，将模型放入开放式研究流程：提出可检验假设、设计模拟、运行实验、迭代解释模糊结果。
* **结果**：前沿模型在生物学、化学、材料科学和物理学中表现大幅下滑，与静态基准的高分形成明显差距；仅扩展模型规模和算力无法弥合该差距，不同厂商的顶级模型共享相同盲点。
* **核心结论**：模型擅长“记住”教科书式答案，但在教科书尚未覆盖的未知循环中会碰壁；当前 AI 并未在真正从事科学发现。

### Karpathy’s Pelican

406 pts · 318 comments · [twitter.com/karpathy](https://twitter.com/karpathy/status/2083749667410727319)

**📌 内容总结**

- 背景：Karpathy 用《魔戒》第一段文字作为唯一 prompt，给 Opus 5 约 1M token 预算（约 $10），要求生成一个 three.js 渲染。
- 关键要点：模型自动运行约 2 小时、写出约 5500 行代码，以程序化方式生成并动画化场景；结果“有点 janky 但有趣”。Karpathy 认为这类“没人会手动做”的定制内容，会因 LLM 的低成本变成可消费品，并设想“按需生成的临时 GTA 式世界”。
- 限制与影响：他同时指出 LLM 很难审计这类输出——不能原生看视频或玩游戏，只能靠截图检查，因此出现多处穿模/错乱；多模态与游戏内交互能力仍是当前短板。
- HN 关注点：该实验更像有效的新基准，还是社交媒体的 token 燃烧 demo？模型能力提升是否被高估？Karpathy 的身份和商业立场如何影响叙事？

**💬 讨论总结**

- 新基准 vs 旧基准：多数人认为 pelican SVG 已饱和，用长文本→3D 动画测试空间推理是自然延伸；但也有人指出这类任务昂贵、难量化，只是“面向 Twitter 的注意力测试”，真实评测应来自自身业务 traces。
- 能力归因：有评论怀疑 Anthropic 专门强化过 three.js 生成，不能外推；反驳者认为从模糊文学段落到 3D 坐标、材质、动画需要大量隐式物理和空间知识。有用户分享用 Claude 做 WebGL 迁移和性能优化的实际经验，表示模型对 3D 与加载性能的理解确实很强。
- Karpathy 公信力争议：部分评论批评他 8 个月前还说“可靠 agent 至少十年后”，现在却展示 Anthropic 产品能力，是营销；支持者指出 8 个月来 agent 能力提升很快，而且这条推文本人就是在指出多模态审计短板，并非单纯广告。
- 游戏行业视角：前游戏开发者认为这类“AI 生成世界”不解决玩家真正要的东西，AI slop 游戏从留存角度基本失败；也有观点认为 LLM 对游戏开发工具链会有实质帮助，只是 demo ≠ 产品。
- 一次性软件讨论：有评论提出“软件变成廉价塑料，坏了就重新生成”的类比，适合一次性任务；反对者认为软件复制成本为零，与实体产品经济模型不同。
- 成本与版权：$10 API 成本不等于“~free”，背后是烧投资人钱；普通用户可能因版权拒绝生成《魔戒》内容，而 Karpathy 有内部访问权限。
- 其他技术点：生成结果明显依赖电影版 Bag End 的训练数据；有建议改用 Blender/USD、分段渲染或 comic 分镜来获得更可控和可比的输出。

### My personal AI benchmark: "Generate an SVG of a frog with a Habsburg jaw."

83 pts · 42 comments · [vaguespac.es](https://frogs.vaguespac.es/)

**📌 内容总结**

- 背景/作者意图：做一个公开、可重复的 AI benchmark：同一 prompt 下，让多个模型生成 “frog with a Habsburg jaw” 的 SVG，每个模型当月 3 次机会，并展示原始输出、耗时、体积和 SVG 内注释。
- 关键要点：该 prompt 同时要求解剖特征和世界知识（Habsburg 家族史），能观察模型如何理解指令、是否会自行脑补。当前数据：14 个模型、42 次运行全部返回 SVG；Claude Opus 5 被多数评论认为最接近“人类作品”。
- 观察/限制：不同模型行为差异明显——7/14 个模型自动引入皇室元素；Mistral 两次运行输出字节级相同；Gemini 在 SVG 里写了 65 条注释，Llama 不写注释。站点因 HN 流量一度过载。
- HN 关注点：这类 benchmark 能否衡量“生成训练集外内容”的能力？指令遵循和确定性比画得好看更值得关注？

**💬 讨论总结**

- 共识：这是一个比 pelican 更有效的方向。它把“解剖学特征 + 历史知识”绑在一起，能区分“忠实执行指令”和“自作主张扩展”；模型对 Habsburg jaw 的联想（皇冠、皇室肖像）成为指令遵循的讨论焦点。
- 工程经验：有评论指出这类测试和实际编码体验一致——模型能把局部细节画对，但整体结构常不合理。分享者提议增加侧脸、分镜等约束；也有评论将它与 MacBook SVG benchmark 类比。
- 历史背景：Habsburg jaw 即 mandibular prognathism，因哈布斯堡家族近亲通婚而著名。这个背景知识本身就是模型跑题/发挥的诱因。
- 反对/质疑：有人质疑这类随机任务不代表实际使用价值，回复认为它能测试模型处理训练集外概念的能力；另一条评论认为这是“为 AGI 叙事服务”的意识形态驱动，而非实用评测。
- 风险/限制：当前所有模型产出的 SVG 仍与人类艺术差距明显，评分主观；网站流量洪峰也说明这类视觉 benchmark 容易成为社交传播热点，而非严谨评测。

## 今日洞察

VitaBench 2.0 给出反直觉结果：接入记忆模块后多数模型性能不升反降，Claude-Opus-4.6 开卷均分刚过 0.5；所有模型在主动提问任务上断崖下跌（Claude 家族 46.0→27.4）。长期记忆不是 Agent 的补丁——瓶颈不在“记住什么”，而在“何时该问、何时该动”。DeepSeek-V4-Pro 这类强模型的失败点已不在工具使用，而在偏好理解：工具调用正成为基准中的常量，真实分化在交互策略。
