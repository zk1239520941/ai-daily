Meta 开源 30B 模型 Muse Glimmer，并预告开源旗舰 Muse Spark 1.2

  • 模型发布：Meta 超级智能实验室（MSL）推出 Muse Glimmer——30B 稠密参数、120K+ 上下文窗口的开放权重模型，Apache 2.0 许可，可在 24GB 显存消费级 GPU 上运行；官方称其在 MCP Atlas、DeepSearch QA、SWE-Bench Verified 等 Agent 基准上领先同尺寸模型。
  • 生态 Day-0：Hugging Face 同步上线权重与 GGUF 版；Ollama 通过 MLX 引擎原生支持 Apple Silicon；vLLM、SGLang 均为 day-0 支持，SGLang 实测 RTX 5090 约 230 tok/s；NVIDIA 称单 GPU 吞吐最高 20K tokens/s。
  • 榜单首秀：LMArena 数据：Text Arena 第 97（开源模型第 24）、Code Arena: WebDev 第 77（开源第 26）。
  • 配套动作：扎克伯格同日发布长文《The Future Is for Everyone》，主张超级智能分配给个人，批评 Google/Anthropic/OpenAI 的封闭路线；MSL 负责人 Alexandr Wang 确认后续将发布 Muse Spark 1.2 的开放权重版本。
  • 术语争议：Gary Marcus 借 NYT 混淆概念指出，Muse 系列是 open-weight 而非 open-source——权重可下载，训练数据与完整训练流程不可得。

Claude 未证明黎曼猜想，但将零点临界线比例下界从 41.6% 推至 67.2%

  • 发起过程：Anthropic 员工 Jarred Sumner（非数学家）在 Claude Code 中下达"认真试试黎曼猜想"；Claude 先尝试约 650 个思路全部失败，随后用一天半协调约 60 个子智能体——2 个负责核心数学思路、13 个提供想法、13 个做验证、2 个协助写论文，共运行 2400 条命令，两轮合计消耗约 3100 万输出 token。
  • 数学突破：将黎曼 ζ 函数非平凡零点位于临界线上的已知比例下界，从 2020 年的 41.6% 一举提升至 67.2%，单步跨越约 26 个百分点，是该问题 80 年来最大的一次单步推进。
  • 验证：Anthropic 数学家 Levent Alpöge、Ralph Furman 完成审查；外部数论专家 Brian Conrey、Dan Goldston 初步审阅；Claude 用 Lean 写出了机器可验证的证明。
  • 行业坐标：Anthropic 明确表示该路线不太可能直接证明黎曼猜想本身；这是继三周前 Claude Fable 5 推翻 Jacobian 猜想一般形式后，模型第二次在数学家长期未推进的前沿问题上给出可验证成果——从"解题"走向"原创数学研究"。
    🔗 Jarred Sumner 推文 | 宝玉解读 | 爱范儿早报

OpenAI 发布网络安全模型 GPT-5.6-Cyber，扩展 Daybreak 计划

  • 模型定位：GPT-5.6-Cyber 是 OpenAI 首个面向高级、授权网络安全工作的大规模模型，覆盖漏洞利用开发等任务；访问仅限获批防御者，高风险工作附加监控与管控。
  • 实战背书：OpenAI 称模型已在真实漏洞研究中广泛使用，发现了 Chrome v8 引擎等流行开源软件中此前未知的漏洞，并用于内部红队与防御体系。
  • 高管动作：Greg Brockman 称目的是"将前沿智能交到防御者手中"；Sam Altman 直接呼吁开发者"请考虑用我们的模型保卫你的系统"。
  • 时间坐标：继昨日将 Astra 列为 Critical 级网络安全模型后，OpenAI 连续两天强化"防御者优先"的发布节奏，网络安全正成为前沿模型能力分级与发布策略的核心场景。

Anthropic 为 Claude 输出启用隐形文本水印与 C2PA 元数据

  • 两层标记：文本层嵌入人眼不可见的水印，通过同义词选择等微决策携带印记，复制粘贴与轻度编辑后仍可检测；文件层为 SVG、PNG、JPG 等生成物附加 C2PA 标准数字签名元数据。
  • 生效范围：8 月 2 日起发布的所有新 Claude 模型；API、Claude 官网、Claude Code、Claude Cowork、Claude Tag 全产品线适用；通过 AWS、Google Cloud、Microsoft Foundry 调用同样生效。执行不限于欧盟，全球统一。
  • 合规背景：为遵守欧盟 AI 法案第 50 条签署的透明度准则；Anthropic 正在开发配套检测工具，未来将开放第三方检测。
  • 已知局限：检测到水印仅代表"可能经过 Claude 处理"，无法确证原始作者；重度改写、短文本、格式转换都会使信号失效。Paul Graham 当天即提出"改写输出以破坏水印"作为创业方向。

Muse Glimmer: 30B-parameter model optimized for always-on local agent workflows

1045 pts · 579 comments · meta.ai

📌 内容总结

  • Meta Superintelligence Labs 发布 30B 开放权重模型 Muse Glimmer，Apache 2.0 许可，定位“always-on 本地 agent 工作流”：单消费级 GPU 可运行，覆盖函数调用、本地编码、LLM-as-judge。
  • 训练采用 logit distillation（教师为更大的 Muse Spark），经过长上下文/agent 数据 mid-training 与 SFT+RL post-training；官方量化至约 4-bit 后语言模型 <20GB，配合 DFlash 投机解码可在 24GB/32GB 设备运行。
  • 官方 benchmark 对比 Gemma4-31B 与 Qwen3.6-27B，并公布解码加速数据：RTX 5090 3.1x、M5 Max 1.8x、M4 Max 1.5x。
  • 限制：全精度需 >55GB；dense 架构在无 HBM 的 DDR5 平台上受内存带宽瓶颈；真正“消费级”仍需 24GB 以上 VRAM 或 64GB 统一内存。
💬 讨论总结
  • 共识：Meta 回归开放权重是积极信号；24–32GB VRAM 级别的竞争加剧对用户有利。
  • 工程经验：预量化 + 投机解码 drafter 是“开箱即用”的关键；llama.cpp 支持已合并，开发者实测 7900XT 上 Q4 约 36 tok/s、Q3 约 60 tok/s（无 MTP）。
  • 反对 / 质疑：很多人纠正 Meta 是“open weights”而非“open source”；基准对比对象是上一代 Qwen3.6，社区普遍预期即将发布的 Qwen3.8 27B 会反超。
  • 历史背景：Meta 曾在 Llama 时期靠“泄露”开启开放权重生态，本次 Apache 2.0 许可比 Llama 系列更宽松，被视为修复开发者关系的策略。
  • 风险 / 限制：即使量化后仍需 24–32GB RAM，对多数用户而言低成本 API 模型（如 DeepSeek V4 Flash）比本地 30B 更实用。

Show HN: Needle2: 14MB agentic LLM for phones, wearables, smart home and robots

177 pts · 77 comments · cactuscompute.com

📌 内容总结

  • 作者想做什么：Cactus Compute 发布 Needle 2——45M 参数、14MB 二进制、28MB 峰值 RAM 的 agentic 模型，面向 <$200 设备（手机、可穿戴、智能家居、机器人、MCU）上的工具调用与设备控制；Apache 2.0。
  • 解决的问题：把“自然语言 → 函数名 + 参数”这一受限映射做到足够小，设备控制不需要庞大世界知识，因此 45M 参数足够。
  • 技术实现：Simple Attention Network（Hadamard MLP 降低参数、engram 哈希表按需读取世界知识）；CQ2-bit 量化从训练开始（QAT），非事后量化；字节级 grammar 约束解码可跳过最多 98% 词表投影；256-token 滑动窗口，工具声明固定为 permanent sinks；单 C++ 二进制启动时自选 kernel。
  • 用户反馈焦点：演示中“turn on tv → lock_door”、“make it warmer → 65°F cooling”等误判引发质疑；但也有 Pebble 生产案例和社区对微模型 + 上层 LLM 分层架构的肯定。
💬 讨论总结
  • 共识：微模型方向被低估，适合作为层级 LLM 中的最小工具调用层；默认权重不能当通用助手用，需要针对具体工具集微调。
  • 工程经验：小模型必须训练时量化（QAT），事后量化会崩溃；语法约束不仅能保证格式，还直接削减算力；固定工具声明可避免长会话中的“工具遗忘”。
  • 风险 / 限制：45M 参数缺少语义理解，模糊查询上容易产生错误工具映射；多个错误调用虽带低 confidence，但校准仍有问题，需要上层策略兜底。
  • 反对 / 质疑：有评论认为 14MB 的大小选择“任意”，web demo 表现接近“随机句子生成器”；作者回应称目标不是通用对话模型。

Claude 将黎曼零点比例下界从 41.6% 推至 67.2%。产出方式更说明问题：约 60 个子智能体、2400 条命令、3100 万输出 token，用 Lean 产出机器可验证证明。前沿数学瓶颈随之移到"多 Agent 编排 + 形式化验证"基建栈——Lean 是可信度闸门，数学家审阅只是流程收尾。两轮 3100 万 token 换一篇可验证成果，科研人力与 Agent 算力的性价比对比正在重写；能复制该流程的团队，决定因素是验证闭环的成熟度，不是模型规模。

本地 Agent 同日出现两个极端：Muse Glimmer 是 30B/24GB 的 always-on 大脑，Needle2 是 45M/14MB 的设备端工具调用层。HN 认可后者落在分层架构——微模型做函数映射、上层大模型做语义兜底。消费级 Agent 默认形态正在分裂：设备端只保留训练时量化与语法约束解码换来的最小可运行层，内存带宽与显存预算仍是本地推理的真正上限。
