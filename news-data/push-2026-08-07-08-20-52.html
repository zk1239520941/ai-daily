项目定位：
面向 AI 编程 Agent 的本地优先代码知识图谱引擎。解决大仓库代码审查与修改任务中"重复读取全库、上下文窗口被无关文件填满"的问题。与向量 embedding/RAG 方案不同，它基于精确静态分析构建代码图谱，并通过 MCP 将最小化上下文提供给 Agent。

核心功能：
- 使用 Tree-sitter 将代码解析为 AST，构建包含函数、类、调用关系、继承与测试覆盖的持久化图（SQLite）。
- 变更时执行 blast-radius 分析，仅返回受影响的调用方、依赖方与测试文件，压缩审查上下文。
- 增量更新：通过 git diff + SHA-256 哈希只重解析实际变更文件，约 3000 文件仓库中两次编辑可在 2.5 秒内完成重索引。
- 自动检测并配置 Claude Code、Codex、Cursor、Gemini CLI、Copilot、Windsurf、Zed 等主流 Agent 工具，通过 MCP 暴露上下文查询接口。

技术亮点：
基于 Tree-sitter 静态分析 + SQLite 图结构而非 embedding 检索，在测试仓库上实现 68x 的 token 缩减；支持增量索引与跨平台 MCP 接入。

AMD acquires Taalas to boost inference performance by etching models in silicon

302 pts · 240 comments · theregister.com

📌 内容总结

  • 背景：AMD 收购多伦多 AI 芯片创业公司 Taalas；其做法是把模型权重直接“蚀刻”进硅片，称为 MSIC（模型专用集成电路）。交易未披露金额，预计 Q4 完成，定位与 Nvidia 花 $20B 授权 Groq 类似，目标是把推理做到更快更便宜。
  • 技术要点：HC1 测试芯片在 TSMC 6nm 上把 Llama 3.1 8B 跑到 16,960 tok/s，发布时号称比 Nvidia GPU 快 48 倍、比 Cerebras 快 8.5 倍。第二代 HC2 目标单芯片 20B 参数，万亿参数模型约需 50 颗加速器。芯片分为 mask-ROM 权重区域与 SRAM 的 KV cache/LoRA 区域，本质是存内计算、非冯诺依曼架构。
  • 限制/影响：模型被固化，升级需要重流片；据称只需换两层 metal 层，但仍需数周至数月。预期主要客户是模型开发商、基础设施商和少数推理服务商；可能搭配 AMD Helios 机架，GPU 做 prefill，Taalas 芯片做 token generation。
💬 讨论总结
  • 速度是真实卖点：chatjimmy.ai demo 被多人贴出，“OMFG this thing is fast”“感觉像魔法”。
  • 核心争议：模型迭代太快，硅片流片出来可能已落后。反对者认为 SOTA 追赶者不该押注；支持者认为大量 agent/工具调用场景只需要“快且便宜”的次代模型，Claude Code 仍用 Haiku 4.5 做子 agent 就是先例。
  • 工程/成本现实：流片周期乐观 2-3 个月，现实 6-12 个月，传统 ASIC 流程可达 2 年；多芯片切分是可行路径，Groq/Cerebras 同样不能单芯片承载大模型。
  • 质疑：AMD 收购后技术可能被大组织吞掉，落地遥遥无期；也有评论指出 SOTA 架构正在收敛，ASIC + LoRA 适配器的“硬件即服务”模式可能成立。

Humans missed 1 in 3 threats approving AI agent commands across 40k game runs

243 pts · 187 comments · scalex.dev

📌 内容总结

  • 作者为“AI agent 命令审批”小游戏加入统计：40k 次游戏、409k 次 approve/deny。玩家需要在一分钟内审阅命令，放行或阻止恶意操作。
  • 结果：平均漏过 1/3 威胁。明显破坏性命令漏过率 11.7%，凭据读取/外传类漏过率 33-35%。最容易被放行的是 npm run analyze/setup/deploy：即使历史日志里能看到 payload，仍有 52.5% 被批准，接近其他外传类攻击的两倍。
  • 另一侧是过度拦截：npm config set registry https://npm.internal 被 59% 玩家拒绝，rm -rf dist/ 被 45% 拒绝。作者承认游戏威胁密度远高于真实场景，但认为疲劳和“npm run 盲区”是真问题。
💬 讨论总结
  • 共识：逐条弹窗不是安全机制，只是把责任转移给用户；有评论直接称其为“model vendors 的 CYA click-thru”。
  • 工程方案集中在结构性防护：sandbox、文件级权限、allowlist、AI 预筛命令、网络隔离；目标是“让整类失败无法发生”，而不是靠人盯。
  • 反对/质疑：游戏没有真实后果、有倒计时、威胁密度和标答存在争议，因此不适合推广为“人类不可靠”的证据；有玩家指出不点击任何按钮也能赢。反驳者认为现实中的 agent 命令更隐晦，且很多人让 Codex 无人值守跑通宵，表现只会更差。
  • 历史参照：有评论引用苏联 GOST 工业标准，认为人类可接受错误率通常在 5% 左右，33% 从未被视为可接受。
