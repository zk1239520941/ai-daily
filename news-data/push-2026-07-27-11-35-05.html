美团正式发布 LongCat-2.0：万亿参数模型，国产算力全栈训推

  • 核心发布：美团正式发布新一代万亿参数大模型 LongCat-2.0（总参数1.6T，平均激活约48B），并宣布开源。该模型是业界首个在5万卡国产算力集群上完成全流程训练与推理的万亿参数模型，从零开始预训练，原生支持1M超长上下文。
  • 关键数据：预训练数据规模超 30T tokens；在 SWE-bench Pro 上得分 59.5，超过 Gemini 3.1 Pro（54.2）、GPT-5.5（58.6）和 Claude Opus 4.6（57.3）。预览版已跻身 OpenRouter 全球大模型调用量前三。
  • 技术亮点：采用 LongCat Sparse Attention（LSA）稀疏注意力机制、零计算专家 + ScMoE 实现 token 级动态激活（33B~56B），并通过 MOPD 多专家融合架构整合 Agent、Reasoning、Interaction 三组能力。
  • 行业意义：LongCat-2.0 证明了国产算力集群具备万亿参数模型的全流程训推能力，其在 Agentic Coding 和复杂办公场景上的表现，为国内企业级 Agent 落地提供了强有力的自主算力基线。

美团开源 LoHoSearch：难度可调的搜索智能体评测基准

  • 核心发布：美团 LongCat 团队开源 LoHoSearch，一个基于知识图谱自动化构造的搜索智能体评测基准，通过系统控制搜索空间与结构复杂度，生成难度显著高于现有基准的题目。
  • 关键数据：最强模型 GPT-5.5 准确率仅 34.74%，远低于其在 BrowseComp 上的表现。现有上下文管理策略在 LoHoSearch 上提升幅度（6.8%）远低于 BrowseComp（14.03%），表明长程搜索中的信息丢失问题仍是核心瓶颈。
  • 行业意义：LoHoSearch 揭示了当前搜索 Agent 在长程、多跳任务上的能力断层，为下一代上下文管理技术提供了更具价值的试验场。

美团开源 MineExplorer：首个开放世界分钟级长程任务评测基准

  • 核心发布：美团 LongCat 团队开源 MineExplorer，系统评测多模态大模型在动态、需持续探索的开放世界中的长程规划能力。包含 813 个人工验证的高质量实例，配套规则化里程碑自动评测框架。
  • 关键发现：在 18 款顶级模型测试中，表现最好的 Claude-Opus-4.6 整体成功率仅 41%。60% 的失败源于导航问题，且增加步数和记忆帧并非解药。核心瓶颈在于：模型感知能力优于推理能力，后者难以将观察转化为长程行动计划。
  • 行业意义：MineExplorer 揭示了从“看见世界”到“探索世界”的巨大鸿沟，为具身智能领域提供了诚实、可量化的能力基线，也为后续长程训练提供了可扩展的练兵场。

[持续跟踪] 社区共识：Opus 5 指标虚高，通用基准测试“几乎完全失效”

  • 前情提要：Anthropic 推出的 Claude Opus 5 在多个公开基准测试上超越了 Fable 5，但其实际使用体验与社区预期产生落差。
  • 最新进展：Kun Chen、Ramez Naam 等多位 KOL 及安全研究员今日发文指出，Opus 5 的基准优势很可能源于针对特定评测的定向训练，而非通用推理能力的本质提升。Gary Marcus 转引观点认为，这再次证明“训练至基准”不等于“通往 AGI”。社区普遍认为，当前流行的通用基准已无法区分模型真实能力，未来的评测需转向由私有数据集或基于知识图谱的动态生成。
  • 行业意义：这一共识的达成，标志着 AI 评测范式正从“静态榜单竞争”向“动态任务验证”切换。这对于那些依赖公开排行榜评估模型能力的组织和投资者，是一个重要的警示信号。

开源模型安全性的深度讨论：草根黑客仍偏爱订阅制 API

  • 核心观点：在关于开源模型安全性的一条深度讨论中，一位前 Anthropic 研究员指出，尽管开源模型（如 GLM 5.2）在渗透测试中能力更强，但他接触的黑客仍然使用 Claude Code 或 Codex 的订阅版进行攻击。原因在于：订阅 API 更稳定，不需要特定越狱，且通过灰色市场的折扣 token 可低成本获取。
  • 行业意义：该观点挑战了“开源模型更危险”的简单叙事。实际上，对于中等水平的恶意行为者，商业 API 的易用性和稳定性构成了更大的现实风险。这为 AI 安全政策制定提供了新的思考角度：限制模型权重可能不如精细化管控 API 访问和滥用检测来得有效。
    🔗 Thomas Wolf 转发推文

The New AI Superpowers: Focus and Followthrough

162 pts · 49 comments · site

📌 内容总结

  • 作者反思 AI 提高效率后反而导致 burnout：他能同时启动 40+ 个“概念验证”项目，但每个项目都是一个“开放闭环”，最终导致心理过载。他将此归因于把 AI 省下的时间用在“水平扩张”（做更多事），而非“垂直深耕”（把重要的事做到极致）。
  • HN 关注点:
  • AI 显著降低了“开始”的摩擦力，但并未降低“完成”的门槛。
  • “最后 1%”（生产级打磨）所需的精力可能占整体 50-90%，AI 主要加速的是前 90%，而非那 1%。
💬 讨论总结
  • 共识观点：AI 确实让“探索可能性”变得极其廉价，但也因此产生了新的组织与管理挑战。多位评论者表示，自己并行项目数量大幅增加，但“做完”的能力并未同步提升，“聚焦”和“完成”反而是 AI 时代更稀缺的技能。
  • 工程经验：
  • 多位有实践经验的开发者建议：将 AI 定位为“辅助栈”工具（处理配置、容器、测试、UI 等非核心逻辑），而不是用来生成整个产品。这样既能放大效率，又不会导致项目失控。
  • 有评论者采用固定周期管理：在 Obsidian 里写 spec → 后台启动 agent → 审查、合并、发布。通过流程化而非并发来维持可控节奏。
  • 反对/质疑：
  • 多位评论者质疑文章前提“AI 带来 100x 效率提升”。他们认为 100x 的代码量不等于 100x 的真正产出，尤其是最后 10% 的生产级打磨，AI 生成的代码往往是“hack on top of hack”，质量堪忧。
  • 有评论者观察到组织层面的副作用：每个人都觉得“靠 AI 几个小时就能搞定”，导致大量重复的、不兼容的“玩具项目”涌现，且无人愿意处理无法自动化的瓶颈环节。他们认为这是“组织价值函数滞后于技术”的表现。

今日洞察

Agent 落地正从"能力溢出"阶段进入"信任瓶颈"阶段。 今天两个独立信号指向同一问题：OpenAI 演示的 ChatGPT Work 已经能凭一条指令完成规划、建站、预订全流程——技术面基本就绪。但 Peter Yang 在加拿大的用户调研显示，普通用户对 AI 的最大担忧不再是性能，而是"是否足够信任它连接我的 Gmail、日历、Workspace"。这个矛盾的实质是：Agent 的实用边界已经从模型能力转向数据权限的授权机制。谁先解决透明、可控、可撤销的授权体验，谁就能吃掉 Agent 落地的第一波红利。ChatGPT Work 的技术复杂度很高，但其商业爬坡曲线将被用户信任度而非模型能力限制。

评测系统的失效正在从逻辑论证走向商业行动。 针对 Opus 5 指标的社区共识——多位 KOL 和安全研究员指出基准优势来自定向训练——本质上在说一件事：当前公开排名已经无法区分模型的真实推理进步。逻辑上，行业应该从静态榜单转向动态任务验证（如 LoHoSearch 这种难度可控的生成式基准）；但商业上，大量团队正在反向操作——训练至榜单、强控评测集暴露。两者的张力意味着，未来一段时间内，依赖第三方排行榜评估模型能力的投资决策和企业采购决策，都会面临系统性信息不对称。高额研发投入的真实回报率在公开数据层面将更难判断，这可能会倒逼更多公司自建私有评测栈。

AI 项目的重心正从"更强的模型"转向"更好的过程管理"。 今天 HN 热议帖的核心洞见——AI 降低了"开始"的门槛但没降低"完成"的门槛——与 impeccable 和 t3code 这两个 GitHub 项目的现象是同一枚硬币的两面。impeccable 不是加模型能力，而是给编码 Agent 装了一套"设计规范 + 规则引擎"来框定输出质量；t3code 则是给多 Agent 工作流做了一个统一调度层。开发者正在集体意识到：当多个 Agent 的能力趋同时，真正的区别在于你能不能让它们按规范产出、不出界、不并行失控。这并不是某种"范式转向"，而是工程成熟度的自然爬坡——当基础能力不再是瓶颈，瓶颈就变成了流程管理。这个趋势对开发工具链的投资方向有直接含义：Agent 编排、规则引擎、项目管理集成可能比下一个更强的基础模型更有投资价值。
