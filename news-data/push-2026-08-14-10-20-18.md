### 1. Google 发布 Gemini 3.7 Flash：价格减半，当天接入主流编程工具

* **核心发布**：Google DeepMind 推出 Gemini 3.7 Flash，官方定位为"最强的 coding/agent 工作型模型"，距离 3.6 Flash 发布仅三周。
* **定价**：输入 $0.75/百万 token、输出 $3.75/百万 token（至少到年底），较 3.6 Flash 低 50%；OpenRouter 额外提供 5 折至 8 月 27 日。
* **基准表现**：LMArena Text Arena 第 9（1490 分）、Code Arena WebDev 第 8（1588 分）、Agent Arena 第 20；Zapier AutomationBench 首次突破 30%，成为首个越过该线的模型，Marketing/Finance/Sales 分域领先。
* **生态接入**：上线首日已进入 AI Studio、Antigravity、Cursor、GitHub Copilot、Devin、Poe、OpenRouter 与 AI SDK；Devin 称其在 FrontierCode 1.1 上以不到一半成本达到 Claude Sonnet 5 级性能。
* **争议**：Simon Willison 质疑"introductory pricing"将在 12 月 31 日翻倍；路透同日报道 Gemini 新旗舰因内测性能落后被推迟两个月。

### 10. 微软新论文：坏 Skill 对 Agent 的代价是可测量的

* **研究方法**：Microsoft 团队通过对比"加载某个 Skill"与"不加载该 Skill"的匹配运行，将 307 次 Agent 失败归因到具体 Skill——125 次功能性失败、182 次效率回退。
* **核心发现**：失败很少来自无关 Skill；看似相关的 Skill 会诱导 Agent 错误实现或遗漏任务要求。成本回退也非 prompt 长度导致，最大来源是过度验证（67 例）与重型实现流水线（30 例）。
* **行业含义**：为 Agent 生态中"加 Skill 是否免费"的假设提供了首个系统性反证，12 个前沿模型上剔除巧合后的分数平均下降 3.6–7.4 个百分点。
🔗 [论文 arXiv](https://arxiv.org/abs/2608.11888) | [elvis 解读](https://x.com/omarsar0/status/2087926158432309306)

**技术亮点：**  
自研 Simple Attention Network 架构（Hadamard MLP + GQA + n-gram engram 记忆），配合 Cactus Quants 2-bit 量化，将模型与运行时封装为自包含二进制，整体工程完成度较高。

- 模型卡出现“based on Gemini 3.6 Flash”的措辞，引发“是否只是改推理配置”的怀疑；有自称 DeepMind 员工回帖否认，称 3.7 明显不同。

### DeepSeek Harness developer preview

563 pts · 246 comments · [deepseek.com](https://deepseek.com/)

**📌 内容总结**

- 背景：DeepSeek 发布开源（MIT）agent harness 开发者预览版，口号是“Everything is a plugin”，源码一并公开。
- 关键要点：模型、工具、技能、会话、沙箱、存储、循环、调度、UI 全部由 Cordis 插件系统提供；所有模型可见内容写入 append-only session log，支持 Trajectory 回放、fork、恢复与搜索。
- 运行模式：Standard 完整工具集、Code mode 用模型生成的 TypeScript 程序编排多轮工具调用、Minimal 只有 bash + 文件编辑器、Creator 用于在内存中试验插件并组装新模式。
- HN 关注点：可追踪性是否真正领先、插件化是不是过度设计、Node/TypeScript 技术栈与供应链、相对 Claude Code/Pi 的真实定位。

**💬 讨论总结**

- 可追踪性被多数评论视为最突出优势：与 OpenAI/Anthropic 加密或模糊化的 trace 相比，DSH 的 append-only log 能看清 agent 实际看到和执行了什么，对工具开发者尤其有价值。
- 插件化争议两极化。支持者认为 Cordis 的 hot-load/unload、依赖生命周期和副作用清理解决了插件系统常见问题，类似 OSGi，且已在 Koishi 项目中用了四年；反对者认为“everything is a plugin”最终会变成插件碎片化、无治理，并有人讽刺“skill”只是用 prompt 重新发明 git hooks 和 pre-commit。
- Node/TypeScript 选型被广泛批评：下载 47MB、构建后 1.5GB、35 个依赖占 1.4GB，供应链安全与 npm slop 被反复提及；也有辩护认为 Node 适合异步、跨平台、快速迭代，且 LLM 写 TypeScript 门槛低。
- 定位与 benchmark 仍不清楚：README 信息量太少，无法判断相对 Claude Code / Pi / OpenCode 的实际效果；有评论指出 harness 对比必须看“harness+model”组合，而不是单看一方宣称。
- 早期用户反馈参半：有人用 Bun + 本地 9B 模型跑小型 Python 项目，认为连接简单、速度快；也有人觉得 0.1 版粗糙，API 不稳定属于预期。
- 有自称 DSH 作者的用户现身评论区，承认这是早期 preview，后续会有兼容性破坏；社区普遍认为真正价值要等插件生态成形后再判断。
