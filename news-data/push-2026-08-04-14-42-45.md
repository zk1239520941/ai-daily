**技术亮点：**  
纯 Rust 实现，仅依赖 lopdf，单次文档加载共享检测与提取阶段；官方基准中完整解析 200 份 PDF 耗时 0.47s，显著快于 PyMuPDF4LLM 与 MarkItDown。

### Show HN: Run an 80B Qwen in 4.3 GB of RAM on a Mac, and a 35B on an iPhone

105 pts · 30 comments · [github.com/leonickson1](https://github.com/leonickson1/Swiftlet)

**📌 内容总结**

- 作者想做什么：用 Swift + Metal 写一个 Qwen MoE 推理运行时，只把 dense 核心权重常驻内存，按需从 SSD 流式读取 routed experts，从而让 80B 级模型跑在 Mac、35B 级模型跑在 iPhone 上。
- 关键数据：
  - Qwen3.6-35B-A3B 4-bit：磁盘 18 GB，峰值 RAM 2.6 GB，M5 上约 7-11 tok/s；iPhone 17 约 2.5 GB RAM、约 1 tok/s。
  - Qwen3-Next-80B-A3B 4-bit：磁盘 42 GB，峰值 RAM 4.3 GB，M5 上约 4.5-5 tok/s。
  - 每 token 实际只激活约 3B 参数；作者明确说“聊天像大模型，事实回忆像小模型”。
- 工程要点：专家权重按固定步长打包成 .qpack，单次 `pread` 取一个 expert；不用 mmap，避免 page-cache thrash；LFU+recency 缓存命中率 43-70% 时吞吐基本不变；75% 层用 Gated DeltaNet 线性注意力，没有增长 KV cache。
- 现状/限制：端到端可用，输出正确；当前 decode loop 是 dispatch bound，不是 IO bound；iPhone 速度只有约 1 tok/s。
- HN 关注点：
  - prefill 与 SSD 损耗是否致命
  - 能否通过调大 RAM cache 提速
  - 本地低内存推理是否只是过渡方案

**💬 讨论总结**

- 质疑集中在 prefill 而非 decode：有评论算出 M5 上处理 10k tokens 可能要半小时，认为这点比 decode 速度更影响实用性；回复认为适合过夜后台任务，不适合编码或实时 agent。
- “磁盘交换会杀 SSD”的说法被部分纠正：80B 是 4.5-5 tok/s 而不是“每小时 10 tokens”；另有回应称持续读不一定会造成写入磨损。
- 工程经验：有用户计划在 24-32GB Mac 上增大 RAM cache 来提速；回应指出无法预先知道哪些 expert 会热，缓存收益有限。
- 立场分歧：一方视这类实验为“1T 模型跑在 $200 SSD”的必经之路；另一方认为数据中心并行吞吐的经济性仍会占优，本地模型不会成为 99% 场景的默认选择。
- “Built with Claude Code”被追问合作性质，回复确认只是用 Claude Code 写代码。

### Smaller, faster, safer: running Kimi and GLM at scale

193 pts · 45 comments · [cloudflare.com](https://blog.cloudflare.com/smaller-faster-safer-models/)

**📌 内容总结**

- 作者意图：Cloudflare 介绍在自身推理平台上规模化运行 Kimi/GLM 的量化与 serving 工程，标题给出的卖点是更小模型、更快推理、更高安全性。
- 从 HN 讨论可知，文章核心是 FP8 KV cache 量化：官方称降低内存/延迟的同时不会改变模型答案，并用小上下文 benchmark 支撑“无差异”结论。
- 评论指出的限制：KV cache 量化对质量的伤害可能比权重量化更大；测试只覆盖 Kimi K2.6，缺少 coding/长程 agent 基准；工具调用中的小错误会随时间累积。
- HN 关注点：
  - KV cache 量化是否真的无损
  - 评估基准是否充分
  - 定价与模型页面的透明度

**💬 讨论总结**

- 透明度获得部分肯定：有评论者称很多厂商静默量化 KV cache 却宣传原始权重质量，Cloudflare 主动披露是好事。
- 反对意见同样强烈：只在博客说明、不在模型页警告，对用户可能构成误导；有评论直接称之为“欺诈”。技术上有回复指出权重量化与激活/KV cache 量化是两回事。
- “不会改变答案”被要求用更严格方法验证：应比较 token 概率分布的统计距离，而不是只看最终生成结果。
- 支持证据：vLLM 的 FP8 KV cache 研究也认为精度损失小/可忽略，并包含 LiveCodeBench 6；但评论者仍担心长程任务中的复合错误。
- 商业透明度：博客没有公开价格，只让进 dashboard 查看；有评论转而在 OpenRouter 上找到 Cloudflare 的定价。
- 次要意见：为什么用 int4 而不用 nf4；文章对 LLM serving 讲得太浅；正文被批 AI 味太重，被调侃为“给 agent 读的原材料”；个别评论质疑推理服务不做 Zero Data Retention，形同 honeypot，未获支持。

### MiniMax H3 Day-0 Support in ComfyUI: Open Weights, Native Audio, and 2K Video

285 pts · 85 comments · [comfy.org](https://blog.comfy.org/p/minimax-h3-day-0-support-in-comfyui)

**📌 内容总结**

- 作者意图：ComfyUI 在 MiniMax H3 发布当天提供原生支持；H3 是 MiniMax 第三代视频模型，也是首个开放权重的版本。
- 模型能力：支持文本/图像/视频/音频输入；文生视频、图生视频、首尾帧控制、参考转视频；单段最长 15 秒、最高 2K；音频与视频同 pass 生成，原生立体声而非后期合成。
- 本地优化：ComfyUI 将约 40% 的 modulation weights 剪掉并替换为等价 lookup table，配 int8 convrot 量化，总内存占用从 123.6 GB（全精度）降到 42.5 GB，号称输出质量无损失；配合动态 VRAM offloading 可在 RTX 3060 上本地运行。
- 现状限制：ComfyUI 0.30.0 起可用；权重由 Comfy-Org 托管；Mac 上有人反馈跑不起来。
- HN 关注点：
  - 消费级 GPU 上生成一段视频要多久
  - 与闭源 SOTA 模型的差距
  - 授权条款、版权和影视行业影响

**💬 讨论总结**

- 速度实测：RTX 4070 Ti Super 16GB 生成 10 秒 480p 约 10 分钟；RTX 5080 16GB 同样 10 秒 480p 约 3 分钟；回答“3060 要多久”时约为 10 分钟，另有人指出 3060 没有 16GB 版本。
- 质量评价：多段 demo 被认为比现有开源模型明显强，有人“直接删掉 LTX2 和 WAN”；也有评论认为整体美学仍然 bland/generic，且非正常场景仍会崩坏——例如游戏秀里人被绑在轮子上旋转时，模型有“人头必须朝上”的强先验。
- 版权与授权是主要风险：H3 在 EU/UK/US 等司法辖区有额外授权限制；评论调侃“只要 pinkie promise 不惹迪士尼就能拿 license”。
- 行业影响：有人担心好莱坞/影视行业受影响，训练数据版权问题未解决；也有观点认为导演和剪辑仍有价值，AI 只是把工作变成“排列组合”，而 agentic 剪辑工作流已经在抢占这个环节。
- 竞争背景：有评论认为 H3 仍比 Seedance 2.0/2.5 落后约一年半；开源权重会带来价格压力，也会让创作者绕开平台安全审核。
- 工程问题：modulation weights 用 lookup table 替代的做法被追问是否适用于 LLM，回复指出这通常是 adaLN 类权重，通用 LLM 没有；也有评论联想到 FPGA 上的 LUT 近似。
- 商业化现实：即使开源权重，10 分钟生成几秒 480p 对专业制作不可接受；真正的创作者会在云端开几十个并发生成，本地跑主要是爱好者和规避平台审核。

## 今日洞察

Swiftlet 用 SSD 流式读取 MoE 专家权重：dense 核心常驻、routed experts 按需读取，80B Qwen 在 Mac 上峰值 RAM 仅 4.3GB。瓶颈变成 expert 缓存命中率与 prefill——M5 上 decode 约 5 tok/s，但 10k token 的 prefill 可能要半小时。「聊天像大模型，事实回忆像小模型」：热知识留在缓存，冷知识每次等磁盘。若成立，MoE 路由将开始为磁盘局部性优化，而非只算 FLOPs。

Cloudflare 与 HN 的分歧不在量化本身，而在「无损」的验证标准。官方用最终答案证明 FP8 KV cache 无损，评论者要求比 token 概率分布，并指出 KV cache 量化伤害可能大于权重量化、工具调用小错误会在长任务累积、多数厂商静默量化却按原始权重宣传。后果：同一模型名在不同 serving 商手里已是不同模型，量化不上模型卡，跨平台 benchmark 就失去可比性。

Locus 用 10 个 H100 小时自动后训练的 Qwen3 1.7B 超过官方 Instruct。后训练正从一门手艺变成可计价、可复现的工程；领域定制成本趋近于零后，开源竞争重心落在自动化数据与评估流水线上。
