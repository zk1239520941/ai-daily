### 1. Anthropic 披露 Q2 营收超 115 亿美元，首次实现调整后运营盈利

### 2. Stripe 超 70 亿美元收购 OpenRouter

* **交易状态**：据彭博社援引知情人士，支付公司 Stripe 已敲定收购 AI 模型聚合平台 OpenRouter 的协议，交易价格超 70 亿美元；OpenRouter 数月前融资时的估值为 13 亿美元。
* **平台基本面**：OpenRouter 为开发者提供统一接口，可在不同模型间按任务、价格与性能切换；5 月 B 轮融资时公布的全球用户数为 800 万，可访问 400 多款模型。
* **战略含义**：创始人 Alex Atallah 曾将 OpenRouter 定位为 AI 模型领域的“Stripe”，此次被 Stripe 收购后，模型路由与支付基础设施将进入同一家公司。

### Claude: System Prompts

537 pts · 224 comments · [claude.com](https://claude.com)

**📌 内容总结**

- Anthropic 公开了 claude.ai 与 iOS/Android App 所用核心 system prompt 的版本记录，并明确这些 prompt 不作用于 API；自 Claude 4.6 代起，模型 ID 是固定快照。
- 页面本身是版本索引，真正有价值的信息来自评论区对历史版本的对比和提取：
  - 早期 prompt 只有约 300 词，最新版本已超过 3000 词，被比喻为建筑规范/合同：随着事故和漏洞不断堆叠。
  - Opus 5 的 prompt 中出现了“用户本意是 Fable 5，但被安全路由到 Opus 5”的说明，以及 Fable/Mythos 因美国出口管制暂停、恢复的历史事件补丁，用于弥补模型训练截止时间之后的世界知识。
  - Anthropic 没有公布工具定义和 Claude Code 的 system prompt，社区只能通过间接手段提取。

**💬 讨论总结**

- 共识：system prompt 是“行为层”而非模型权重的一部分；留在上下文里可替换、易迭代，且前缀缓存成本低。把行为“烤进”模型会损失灵活性。
- 工程经验：Simon Willison 把历次 system prompt 整理成 git 提交历史，方便直接查看 Opus 4.8 → Opus 5 的 diff。
- 风险/限制：有人指出 prompt 里已出现相互矛盾的指令，而矛盾指令会降低整体输出质量。“禁止说 genuinely/honestly/straightforward”这类约束也被多人指认无效。
- 反对/质疑：有评论对照泄露的 Claude Code prompt，认为“system prompt 缩减 80%”的说法无法从公开页面对账；回复澄清该数字指 Claude Code，不是网页/App 的 prompt。
- 历史背景：早期 Sonnet 3.5 prompt 完全没有儿童安全相关约束，最新版本已有大量安全 bullet；这种变化是对真实使用事故的响应。

🔗 [原文](https://platform.claude.com/docs/en/release-notes/system-prompts) · [HN 讨论页](https://news.ycombinator.com/item?id=49319556)

### Qwen 3.8 27B is excellent, but it defaults to overthinking things

18 pts · 3 comments · [simonwillison.net](https://simonwillison.net)

**📌 内容总结**

- Qwen 3.8 27B 是 Apache 2.0 许可的 27B 视觉模型，Q4_K_M 量化后约 17GB，可在高配笔记本和 DGX Spark 上运行；官方自报 benchmark 同时超过前代 Qwen 3.6 27B 和闭源 Qwen 3.7-Plus。
- 最大问题是默认 `reasoning_effort=xhigh`：作者实测画一张 pelican SVG 用了 21 分钟、22,276 个思考 token 才产出 3,223 个输出 token；关闭 reasoning 后同样任务 137 秒完成。
- 关闭 reasoning 后输出质量明显下降，但“画一个圆”这种请求在 xhigh 下会被扩展成复杂的动效设计，说明默认档位严重过度思考。
- 优点：bounding box 检测非常准；能驱动 Pi 完成真实 coding agent 任务；能自己写 Python 工具处理 JSONL 转换。
- 速度仍是瓶颈：LM Studio 下约 15–30 token/s。llama.cpp 的 MTP 投机解码（`--spec-type draft-mtp`）可带来约 72% 的性能提升。

**💬 讨论总结**

- 共识：dense 模型的 token 生成速度本来就慢，默认 xhigh 会把大量时间烧在无意义的思考 token 上，不适合消费级硬件。
- 工程经验：有用户对比 Qwen 35BA3B 与 27B，认为速度差距约 7–8 倍；更值得关注的是 Muse 30B 这类“极少废话、token 更高效”的模型。
- 现实约束：一位用户用同一代理任务横向对比多个模型，Qwen 27B 是自托管模型里效果最好的，但在双 GPU 机器上跑了 11 小时；GPT-5.5 约 20 分钟，大多数大模型约 1 小时。
- 明确倾向：agent 场景下 token 效率就是运营成本，宁可要一个“默认简短、只对困难问题升级处理”的模型，也不要每个工具调用都先长篇思考。

🔗 [原文](https://simonwillison.net/2026/Aug/16/qwen-38-27b/) · [HN 讨论页](https://news.ycombinator.com/item?id=49324985)

### Stripe Clinches over $7B Deal to Buy AI Firm OpenRouter

189 pts · 139 comments · [bloomberg.com](https://www.bloomberg.com)

**📌 内容总结**

- Bloomberg 报道 Stripe 已完成对 OpenRouter 的收购协议，交易金额超过 70 亿美元；几个月前 OpenRouter 融资时估值还只有 13 亿美元。
- OpenRouter 以单一 API 代理数百个模型，帮助开发者切换不同 LLM 提供商；Stripe 借此进入 AI 基础设施与 token 计费市场。
- 对 Stripe 而言，OpenRouter 本身已是 Stripe 支付客户；收购既能收编支付流水，也能为未来“按用量计费的 AI 产品”提供统一支付和结算层。

**💬 讨论总结**

- 战略解释：Stripe 和 OpenRouter 本质上都是“一个 API Key 面对碎片化生态，赚取通道费”的模式。评论区认为 Stripe 想成为 AI 时代的支付+模型分发层，甚至延伸到“token 钱包/跨服务订阅”，把 AI 计费抽象成类似 Stripe 现有金融产品的形态。
- 现实背景：OpenAI 刚宣布把支付从 Stripe 换到 Adyen；OpenRouter 聚集了大量模型 API 支付流水，评论区认为 Stripe 有动机通过收购锁定这部分 AI 相关支付量。
- 反对/质疑：70 亿美元买一个 API 代理是否过度溢价？有人对比其市值超过 Lyft、Dolby 等公司；回复则认为 OpenRouter 握有大量真实 LLM 请求轨迹数据，也是访问低成本中国模型的重要入口。
- 产品澄清：OpenRouter 不是“自动路由/智能选择模型”，而是统一 API 代理；真正价值是切换模型只需要改一个 endpoint。也有人反驳称切换成本也就“改 URL 和 token”，护城河未必深。
- 风险/限制：老用户担心 Stripe 入主后走向 KYC/AML、审查或涨价；也有人担心免费 DeepSeek 通道消失。回复指出免费额度由模型提供商控制，与 OpenRouter 被谁收购关系不大。
- 估值参照：有评论对比 fal.ai 刚以 80 亿美元估值融资，但流量只有 OpenRouter 约 1/5；结论是媒体/创意模型利润率远高于 LLM 代理，OpenRouter 的高估值更多来自战略卡位。

## 今日洞察

Stripe 以 70 亿美元收购 OpenRouter，后者数月前估值仅 13 亿——对一个切换成本只是改 URL 的 API 代理而言，这个价格买的是模型 API 清算通道的卡位。OpenAI 刚把支付迁去 Adyen，Stripe 需要买回 AI 原生支付流水。模型访问正在变成可计费公用事业，结算层将成为利润高地，LiteLLM 这类网关也有了被收购的价值。

Anthropic 公开的 system prompt 历史显示，提示词从约 300 词膨胀到超 3000 词，内含事故补丁、出口管制补丁与相互矛盾的指令。HN 将其定性为"行为层"：模型行为由 prompt 配置，权重只提供基础能力。被低估的后果是评测——单独评估权重意义变小，必须容纳整个行为系统；而矛盾指令会整体拉低输出质量，行为配置复杂度正成为新工程瓶颈。

Qwen3.8-27B 登顶 HF 的同时，Simon Willison 实测暴露开放模型的错位：默认 xhigh 推理让一个 SVG 任务烧掉 2.2 万思考 token、耗时 21 分钟，关闭后仅 137 秒。HN 开发者对比更极端：自托管 Qwen 同一代理任务跑了 11 小时，GPT-5.5 约 20 分钟。agent 场景里推理 token 就是运营成本，"默认简短、困难时升级"会取代"能力最大化"成为模型产品思路——llama.cpp 用 MTP 投机解码换 72% 提速，说明当前解法仍在外挂加速，而非模型自身节制。
