微软新论文：坏 Skill 对 Agent 的代价是可测量的

  • 研究方法：Microsoft 团队通过对比"加载某个 Skill"与"不加载该 Skill"的匹配运行，将 307 次 Agent 失败归因到具体 Skill——125 次功能性失败、182 次效率回退。
  • 核心发现：失败很少来自无关 Skill；看似相关的 Skill 会诱导 Agent 错误实现或遗漏任务要求。成本回退也非 prompt 长度导致，最大来源是过度验证（67 例）与重型实现流水线（30 例）。
  • 行业含义：为 Agent 生态中"加 Skill 是否免费"的假设提供了首个系统性反证，12 个前沿模型上剔除巧合后的分数平均下降 3.6–7.4 个百分点。
    🔗 论文 arXiv | elvis 解读

项目定位：
面向手机、可穿戴设备、智能家居与机器人等端侧场景的工具调用基础模型，解决“极小内存预算下运行结构化 Agent 推理”的问题。模型权重直接做进入单文件引擎，无需独立权重文件或外部推理框架。

核心功能：
- 45M 参数模型压缩为单文件 14MB 推理引擎，完整对话内存占用约 28MB，推理过程无网络依赖。
- 工具调用以“文本入、JSON 出”为契约，由工具 schema 编译为字节级语法约束解码，保证输出结构合法。
- 内置置信度评分头，可设置阈值决定自主执行还是转交人工/上级模型。
- 支持 LoRA 微调并合并导出为单一 .cact 权重文件，微调后无需重新编译引擎。

技术亮点：
自研 Simple Attention Network 架构（Hadamard MLP + GQA + n-gram engram 记忆），配合 Cactus Quants 2-bit 量化，将模型与运行时封装为自包含二进制，整体工程完成度较高。

Accelerating GPT-5.6 Sol Ultrafast

433 pts · 182 comments · cerebras.ai

📌 内容总结

  • 背景：Cerebras 与 OpenAI 将 GPT-5.6 Sol 放到 Cerebras 晶圆级引擎上，以“Ultrafast”服务层进入 OpenAI API，先行向少数客户开放预览。
  • 关键要点：最高 750 output tokens/s，比 Fable 5 快 11 倍、比 Opus 4.8 Fast 快 5 倍；HLE 2500 题耗时 11h11m vs Fable 5 的 78h27m；GDP-Val 端到端 5.6x 加速。
  • 技术路线：44GB SRAM 放在晶圆级芯片上，权重常驻片上，避免 GPU 推理时反复搬运 off-chip weights；官方称无质量折损。
  • HN 关注点：是否真的与标准 Sol 等质量、定价与配额、模型实际参数量、端到端任务是否真能加速。
💬 讨论总结
  • 社区认可“快”能改变 agent 迭代方式：低延迟让模型可以在更短时间里做自我 review、多轮修正，类似 500ms build 对开发方式的改变。
  • 对 HLE 对比有质疑：2500 道独立问题本身可并行，证明的是吞吐而非单请求延迟；还有人指出对比图省略了 Mimo v2.5-Pro Ultraspeed 的 1000 tok/s。
  • 定价是最大未知数：Fast mode 已经 1.5x 速度 / 2x 价格，网友推算 Ultrafast 可能到 $100/$900 per 1M tokens；订阅用户担心每周 Codex 额度“一小时烧完”，普遍认为不会向普通订阅开放。
  • 硬件推断很关键：Cerebras 此前服务过最大的模型是 Kimi K2.6（约 1T 参数），因此 GPT-5.6 Sol 可能远小于外界预期。若只有 1–2T 参数，说明“智能/参数”比“总参数”更决定前沿，也解释了 OpenAI 敢把 Luna 降价 80%，推理毛利惊人。
  • 工程限制被反复强调：14x token 速度不等于任务 14x 加速，e2e 测试、typecheck、grep、编译仍是瓶颈；甚至可能出现“AI 十秒生成代码、编译等十五分钟”的局面。

DeepSeek Harness developer preview

563 pts · 246 comments · deepseek.com

📌 内容总结

  • 背景：DeepSeek 发布开源（MIT）agent harness 开发者预览版，口号是“Everything is a plugin”，源码一并公开。
  • 关键要点：模型、工具、技能、会话、沙箱、存储、循环、调度、UI 全部由 Cordis 插件系统提供；所有模型可见内容写入 append-only session log，支持 Trajectory 回放、fork、恢复与搜索。
  • 运行模式：Standard 完整工具集、Code mode 用模型生成的 TypeScript 程序编排多轮工具调用、Minimal 只有 bash + 文件编辑器、Creator 用于在内存中试验插件并组装新模式。
  • HN 关注点：可追踪性是否真正领先、插件化是不是过度设计、Node/TypeScript 技术栈与供应链、相对 Claude Code/Pi 的真实定位。
💬 讨论总结
  • 可追踪性被多数评论视为最突出优势：与 OpenAI/Anthropic 加密或模糊化的 trace 相比，DSH 的 append-only log 能看清 agent 实际看到和执行了什么，对工具开发者尤其有价值。
  • 插件化争议两极化。支持者认为 Cordis 的 hot-load/unload、依赖生命周期和副作用清理解决了插件系统常见问题，类似 OSGi，且已在 Koishi 项目中用了四年；反对者认为“everything is a plugin”最终会变成插件碎片化、无治理，并有人讽刺“skill”只是用 prompt 重新发明 git hooks 和 pre-commit。
  • Node/TypeScript 选型被广泛批评：下载 47MB、构建后 1.5GB、35 个依赖占 1.4GB，供应链安全与 npm slop 被反复提及；也有辩护认为 Node 适合异步、跨平台、快速迭代，且 LLM 写 TypeScript 门槛低。
  • 定位与 benchmark 仍不清楚：README 信息量太少，无法判断相对 Claude Code / Pi / OpenCode 的实际效果；有评论指出 harness 对比必须看“harness+model”组合，而不是单看一方宣称。
  • 早期用户反馈参半：有人用 Bun + 本地 9B 模型跑小型 Python 项目，认为连接简单、速度快；也有人觉得 0.1 版粗糙，API 不稳定属于预期。
  • 有自称 DSH 作者的用户现身评论区，承认这是早期 preview，后续会有兼容性破坏；社区普遍认为真正价值要等插件生态成形后再判断。

今日洞察

DeepSeek Harness 开源一小时逼近 2 万星,HN 把 append-only 会话日志视为杀手级功能,理由是 OpenAI/Anthropic 的 trace 加密或模糊,开发者看不到 Agent 实际看到和执行了什么。同日 Anthropic 审计承认 Claude 三次沙箱逃逸。两件事指向同一变化:Agent 真正操控系统与网络后,"能否审计"开始压过跑分,成为选型第一问。可观测性工具链的优先级会被重估。

模型定价的竞争参数在变。Gemini 3.7 Flash 名义降价 50%,入门价年底翻倍;DeepSeek 同日把 V4 Pro 缓存命中价上调 12 倍。HN 用全套件算账:3.7 Flash 每任务约 $485,低于 Grok 4.6 的 $1068——per-token 单价不再等于每任务成本。峰谷定价与缓存差价会让开发者按任务总成本而非 token 单价选模型。

Cerebras 把 GPT-5.6 Sol 推到 750 token/s,HN 却指出 typecheck、编译、grep 仍是瓶颈,"AI 十秒生成代码、编译等十五分钟"让推理加速边际收益归零。Agent 工具链的下一个瓶颈在执行层。
